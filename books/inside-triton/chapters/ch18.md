## 一个 kernel 的 TTIR

拿一个最简单的 kernel：`out = x · alpha + y`。

```triton-ir
# IR: ttir
import torch
import triton
import triton.language as tl


@triton.jit
def scale_add(x_ptr, y_ptr, out_ptr, n, alpha, BLOCK: tl.constexpr):
    pid = tl.program_id(0)
    offs = pid * BLOCK + tl.arange(0, BLOCK)
    mask = offs < n
    x = tl.load(x_ptr + offs, mask=mask)
    y = tl.load(y_ptr + offs, mask=mask)
    tl.store(out_ptr + offs, x * alpha + y, mask=mask)


@triton.jit
def row_sum(x_ptr, out_ptr, n_cols, stride, BLOCK: tl.constexpr):
    row = tl.program_id(0)
    acc = tl.zeros([BLOCK], dtype=tl.float32)
    for start in range(0, n_cols, BLOCK):
        cols = start + tl.arange(0, BLOCK)
        acc += tl.load(x_ptr + row * stride + cols, mask=cols < n_cols, other=0.0)
    total = tl.sum(acc, axis=0)
    if total < 0:
        total = -total
    tl.store(out_ptr + row, total)


x = torch.empty(4096, device="cuda")
out = torch.empty(4096, device="cuda")
scale_add[(4,)](x, x, out, 4096, 2.0, BLOCK=1024)
m = torch.empty(64, 1000, device="cuda")
row_sum[(64,)](m, out, 1000, 1000, BLOCK=256)
```

（第二个 kernel `row_sum` 下一节用。）用 3.9.0 编出来的 `scale_add` 的 TTIR，去掉了每一行末尾的 `loc(...)`：

```ttir-norun
module {
  tt.func public @scale_add(%x_ptr: !tt.ptr<f32> {tt.divisibility = 16 : i32}, %y_ptr: !tt.ptr<f32> {tt.divisibility = 16 : i32}, %out_ptr: !tt.ptr<f32> {tt.divisibility = 16 : i32}, %n: i32 {tt.divisibility = 16 : i32}, %alpha: f32) attributes {noinline = false} {
    %c1024_i32 = arith.constant 1024 : i32
    %pid = tt.get_program_id x : i32
    %offs = arith.muli %pid, %c1024_i32 : i32
    %offs_0 = tt.make_range {end = 1024 : i32, start = 0 : i32} : tensor<1024xi32>
    %offs_1 = tt.splat %offs : i32 -> tensor<1024xi32>
    %offs_2 = arith.addi %offs_1, %offs_0 : tensor<1024xi32>
    %mask = tt.splat %n : i32 -> tensor<1024xi32>
    %mask_3 = arith.cmpi slt, %offs_2, %mask : tensor<1024xi32>
    %x = tt.splat %x_ptr : !tt.ptr<f32> -> tensor<1024x!tt.ptr<f32>>
    %x_4 = tt.addptr %x, %offs_2 : tensor<1024x!tt.ptr<f32>>, tensor<1024xi32>
    %x_5 = tt.load %x_4, %mask_3 : tensor<1024x!tt.ptr<f32>>
    %y = tt.splat %y_ptr : !tt.ptr<f32> -> tensor<1024x!tt.ptr<f32>>
    %y_6 = tt.addptr %y, %offs_2 : tensor<1024x!tt.ptr<f32>>, tensor<1024xi32>
    %y_7 = tt.load %y_6, %mask_3 : tensor<1024x!tt.ptr<f32>>
    %0 = tt.splat %out_ptr : !tt.ptr<f32> -> tensor<1024x!tt.ptr<f32>>
    %1 = tt.addptr %0, %offs_2 : tensor<1024x!tt.ptr<f32>>, tensor<1024xi32>
    %2 = tt.splat %alpha : f32 -> tensor<1024xf32>
    %3 = arith.mulf %x_5, %2 : tensor<1024xf32>
    %4 = arith.addf %3, %y_7 : tensor<1024xf32>
    tt.store %1, %4, %mask_3 : tensor<1024x!tt.ptr<f32>>
    tt.return
  }
}
```

逐个概念看。

### op：一行就是一个操作

MLIR 里的一切都是 **op**（operation）。一个 op 的完整样子是：

```
%结果 = 方言.op名 %操作数, %操作数 {属性} : 类型
```

比如 `%x_4 = tt.addptr %x, %offs_2 : tensor<1024x!tt.ptr<f32>>, tensor<1024xi32>`：方言是 `tt`（Triton），op 名是 `addptr`，两个操作数，冒号后面是操作数的类型。点号前面的部分永远是方言名，所以扫一眼就知道每一行属于谁：`tt.` 是 Triton 自己的，`arith.` 是 MLIR 内建的算术方言。`module`、`tt.func` 也是 op，它们的特别之处是**里面装着别的 op**（下一节的 region）。

每个方言的 op 可以定义自己的打印格式（自定义格式），所以 `tt.get_program_id x` 和 `arith.cmpi slt, ...` 读起来各不相同。所有 op 也都能打印成统一的**通用格式**，下一节的 `tt.reduce` 就是。两种格式的规则见《深入 MLIR》第 3 章。

### 值：SSA，名字来自 Python 变量

`%` 开头的是**值**（value）。每个值只被定义一次（SSA，静态单赋值），之后可以被用很多次。Python 里写 `offs = pid * BLOCK + tl.arange(0, BLOCK)` 一行，IR 里变成了 `%offs`、`%offs_0`、`%offs_1`、`%offs_2` 四个值：乘法、`arange`、广播、加法，每一步一个新值。

这些名字不是 MLIR 默认的（默认是 `%0`、`%1`、`%2`……，就像最后几行那样）。Triton 在生成 IR 时，把 Python 的变量名记进了每个 op 的位置信息（`loc("offs")`），打印时又打开了「用位置信息里的名字做前缀」的选项（`python/src/ir.cc` 的 `getOpPrintingFlags()`：`printNameLocAsPrefix(true)`）。所以 `%offs_2` 的意思是「第三个名叫 offs 的中间值」。没有对应 Python 变量的中间结果（比如 `x * alpha + y`），就退回 `%0`、`%1`。读 IR 时，**先找名字，就能对回源码**。

### 类型与属性

冒号后面的是**类型**：

- `i32`、`f32`：标量。
- `!tt.ptr<f32>`：指向 f32 的指针。`!` 开头的是方言自己定义的类型。
- `tensor<1024xi32>`、`tensor<1024x!tt.ptr<f32>>`：1024 个 i32 的张量、1024 个指针的张量。Triton 的「块」在 IR 里就是 `tensor`。

花括号里的是**属性**（attribute）：编译期就确定的常量信息。`tt.make_range {end = 1024 : i32, start = 0 : i32}` 是 `tl.arange(0, 1024)` 的两个端点；`arith.cmpi slt` 里的 `slt`（signed less than）也是一个属性。

最值得注意的是函数参数上的 `{tt.divisibility = 16 : i32}`。这就是第 4 章讲的特化：调用时 `n = 4096` 能被 16 整除，Triton 就给它打上这个标记，编译器后面据此判断对齐。`alpha` 是浮点数，没有这个标记。第 15 章那个 N = 3000 的坑，就是因为 3000 不能被 16 整除，参数上没有这个属性，编译器什么也证明不了。

### 广播变成了显式的 op

Python 里 `pid * BLOCK + tl.arange(0, BLOCK)` 是一个标量加一个张量，靠的是广播。IR 里没有隐式广播：标量 `%offs` 先用 `tt.splat` 变成 `tensor<1024xi32>`（每个元素都是同一个值），才能和 `%offs_0` 相加。`x_ptr + offs` 也一样：指针先 splat 成 1024 个相同的指针，再 `tt.addptr` 逐元素加偏移。二维的情形还会出现 `tt.expand_dims` 和 `tt.broadcast`（第 16 章的 IR 里见过）。**IR 里的每一个类型都是确定的**，Python 里那些「自动」的东西，到这里都变成了看得见的 op。

## 控制流：region 和 block

`row_sum` 有一个循环、一个归约、一个 `if`：

```ttir-norun
    %acc = scf.for %start = %c0_i32 to %n_cols step %c256_i32 iter_args(%acc_1 = %cst_0) -> (tensor<256xf32>)  : i32 {
      %cols = tt.make_range {end = 256 : i32, start = 0 : i32} : tensor<256xi32>
      ...
      %acc_10 = tt.load %acc_9, %acc_5, %cst_0 : tensor<256x!tt.ptr<f32>>
      %acc_11 = arith.addf %acc_1, %acc_10 : tensor<256xf32>
      scf.yield %acc_11 : tensor<256xf32>
    }
    %total = "tt.reduce"(%acc) <{axis = 0 : i32}> ({
    ^bb0(%total_1: f32, %total_2: f32):
      %total_3 = arith.addf %total_1, %total_2 : f32
      tt.reduce.return %total_3 : f32
    }) : (tensor<256xf32>) -> f32
    %0 = arith.cmpf olt, %total, %cst : f32
    %1 = scf.if %0 -> (f32) {
      %total_1 = arith.negf %total : f32
      scf.yield %total_1 : f32
    } else {
      scf.yield %total : f32
    }
```

花括号括起来的那一段叫 **region**：一个 op 里装着的一段代码。region 里是一个或多个 **block**，block 里是一串 op。`scf.for`、`scf.if`、`tt.reduce`、`tt.func`、`module` 都是带 region 的 op。

**`scf.for` 怎样表达「循环里改了 acc」。** SSA 里一个值只能定义一次，可 Python 的循环每一轮都在给 `acc` 赋新值。办法是 **`iter_args`**：`iter_args(%acc_1 = %cst_0)` 说「循环体里有一个值叫 `%acc_1`，第一轮它等于 `%cst_0`（全零）」；循环体末尾的 `scf.yield %acc_11` 说「下一轮的 `%acc_1` 是 `%acc_11`」；循环结束以后，最后一次 yield 的值成为 `scf.for` 的结果 `%acc`。所以**循环里被修改、循环后还要用的变量，都会变成 `iter_args`**。第 12 章 GEMM 的累加器、第 17 章 FlashAttention 的 m、l、acc，都是这么进 IR 的。

**`scf.if` 也有返回值。** Python 里 `if total < 0: total = -total` 给 `total` 重新赋值，IR 里变成了一个「返回一个 f32」的 `scf.if`：两个分支各 yield 一个值，结果是 `%1`。后面的 `tt.store` 存的是 `%1`，不是 `%total`。（`if` 的条件是运行时的值，所以变成了 `scf.if`；如果条件是 `tl.constexpr`，Python 前端在生成 IR 时就选好了分支，IR 里根本不会出现 `if`。第 17 章 `if CAUSAL:` 就是这样。）

**`tt.reduce` 带着一个函数。** `tl.sum(acc, axis=0)` 变成了 `tt.reduce`，它用的是**通用格式**：`"op名"(操作数) <{属性}> ({region}) : (操作数类型) -> 结果类型`。region 里的 `^bb0(%total_1: f32, %total_2: f32):` 是一个 block 的开头，括号里是 **block 参数**：这个 block 被调用时传进来的两个值。block 里只做一件事：把两个数相加，用 `tt.reduce.return` 返回。也就是说，**region 在这里就是一个「合并函数」**：`tt.reduce` 用它两两合并所有元素。`tl.max` 的 region 里是 `arith.maxnumf`，自己写的 `tl.reduce(x, axis, combine_fn)` 的 region 里就是你的 `combine_fn`。

region、block、block 参数在 MLIR 里的完整规则（block 之间怎么跳转、什么时候需要多个 block），见《深入 MLIR》第 2 章。Triton 的 TTIR、TTGIR 里几乎只有单 block 的 region；到了很后面的 `convert-scf-to-cf` pass，`scf.for` 才被拆成多个 block 加跳转。

## 方言：IR 里的「命名空间」

一个 kernel 的 IR 里同时有好几个方言的 op，每个方言管一类事情。下表是在本书的 IR 里出现过的：

| 方言 | 前缀 | 管什么 | 例子 |
| --- | --- | --- | --- |
| builtin | （无） | 模块 | `module` |
| Triton | `tt.` | Triton 语言本身：program id、指针、load / store、dot、归约 | `tt.load`、`tt.dot`、`tt.reduce` |
| arith | `arith.` | 标量和逐元素的算术（MLIR 内建） | `arith.addf`、`arith.cmpi` |
| math | `math.` | 超越函数（MLIR 内建） | `math.exp2`、`math.rsqrt` |
| scf | `scf.` | 结构化控制流（MLIR 内建） | `scf.for`、`scf.if`、`scf.yield` |
| TritonGPU | `ttg.` | 和具体 GPU 无关的 GPU 概念：layout、shared memory、异步拷贝 | `ttg.convert_layout`、`ttg.local_alloc` |
| TritonNvidiaGPU | `ttng.` | NVIDIA 专有：TMA、wgmma、tcgen05、mbarrier | `ttng.warp_group_dot` |
| TritonIntelGPU | `ttig.` | Intel 专有：DPAS、2D block IO、预取 | `ttig.descriptor_prefetch` |
| llvm | `llvm.` | 最后一级，和 LLVM IR 一一对应 | `llvm.intr.assume` |

TTIR 里只有前几行：`tt`、`arith`、`math`、`scf`。从 TTIR 到 TTGIR，`ttg` 和后端自己的方言加了进来；再往后，所有东西都变成 `llvm`。**一个方言就是一组 op、类型和属性**，下表里没有「谁比谁高级」，只有分工。MLIR 内建方言的全景见《深入 MLIR》第 6 章。

## 在浏览器里读一段 IR

读 IR 最常做的三件事：数一数有哪些 op；顺着一个值找它在哪里定义、被谁用；看看循环里有哪些东西其实每一轮都一样。下面的小程序把这三件事都做了，输入就是 `row_sum` 的 TTIR。只用标准库，直接点运行：

```python
# 读 Triton IR：数 op、找定义和使用、找出循环不变量。只用标准库。
# TTIR 是第 18 章 row_sum kernel 的 3.9.0 输出（去掉了 loc(...)）。
import re
from collections import Counter

TTIR = """
tt.func public @row_sum(%x_ptr: !tt.ptr<f32>, %out_ptr: !tt.ptr<f32>, %n_cols: i32, %stride: i32) {
  %cst = arith.constant 0.000000e+00 : f32
  %c256_i32 = arith.constant 256 : i32
  %c0_i32 = arith.constant 0 : i32
  %cst_0 = arith.constant dense<0.000000e+00> : tensor<256xf32>
  %row = tt.get_program_id x : i32
  %acc = scf.for %start = %c0_i32 to %n_cols step %c256_i32 iter_args(%acc_1 = %cst_0) -> (tensor<256xf32>)  : i32 {
    %cols = tt.make_range {end = 256 : i32, start = 0 : i32} : tensor<256xi32>
    %cols_2 = tt.splat %start : i32 -> tensor<256xi32>
    %cols_3 = arith.addi %cols_2, %cols : tensor<256xi32>
    %acc_4 = tt.splat %n_cols : i32 -> tensor<256xi32>
    %acc_5 = arith.cmpi slt, %cols_3, %acc_4 : tensor<256xi32>
    %acc_6 = arith.muli %row, %stride : i32
    %acc_7 = tt.addptr %x_ptr, %acc_6 : !tt.ptr<f32>, i32
    %acc_8 = tt.splat %acc_7 : !tt.ptr<f32> -> tensor<256x!tt.ptr<f32>>
    %acc_9 = tt.addptr %acc_8, %cols_3 : tensor<256x!tt.ptr<f32>>, tensor<256xi32>
    %acc_10 = tt.load %acc_9, %acc_5, %cst_0 : tensor<256x!tt.ptr<f32>>
    %acc_11 = arith.addf %acc_1, %acc_10 : tensor<256xf32>
    scf.yield %acc_11 : tensor<256xf32>
  }
  %total = "tt.reduce"(%acc) <{axis = 0 : i32}> ({
  ^bb0(%total_1: f32, %total_2: f32):
    %total_3 = arith.addf %total_1, %total_2 : f32
    tt.reduce.return %total_3 : f32
  }) : (tensor<256xf32>) -> f32
  %0 = arith.cmpf olt, %total, %cst : f32
  %1 = scf.if %0 -> (f32) {
    %total_1 = arith.negf %total : f32
    scf.yield %total_1 : f32
  } else {
    scf.yield %total : f32
  }
  %2 = tt.addptr %out_ptr, %row : !tt.ptr<f32>, i32
  tt.store %2, %1 : !tt.ptr<f32>
  tt.return
}
"""

OP = re.compile(r'^\s*(?:(%[\w]+)(?::\d+)? = )?"?([a-z_]+\.[a-z_.]+)"?(.*)$')
ops = []                                    # (行号, 结果, op 名, 用到的值, 嵌套深度)
depth = 0
for no, line in enumerate(TTIR.strip().splitlines(), 1):
    m = OP.match(line)
    if m and not line.strip().startswith("tt.func"):
        result, name, rest = m.groups()
        rest = re.sub(r"%[\w]+ = ", "", rest)        # scf.for 里的 %start = …、%acc_1 = … 是定义，不是使用
        ops.append((no, result, name, re.findall(r"%[\w]+", rest), depth))
    depth += line.count("{") - line.count("}")

# ① 每个方言有哪些 op
by_dialect = Counter(name.split(".")[0] for _, _, name, _, _ in ops)
print("① 方言：" + "，".join(f"{d} {n} 个" for d, n in by_dialect.most_common()))

# ② 一个值在哪里定义、在哪里被用到（def-use 链）
for v in ("%row", "%acc_1", "%acc"):
    d = [f"第 {no} 行 {name}" for no, res, name, _, _ in ops if res == v]
    u = [f"第 {no} 行 {name}" for no, res, name, used, _ in ops if v in used and res != v]
    print(f"② {v:7} 定义：{d[0] if d else '循环的 iter_args（块参数）'}；被用到：{'、'.join(u)}")

# ③ 循环不变量：在 scf.for 里面，而且用到的值全都在循环外面定义（或者是常量）
loop = next(i for i, op in enumerate(ops) if op[2] == "scf.for")
end = next(i for i in range(loop + 1, len(ops)) if ops[i][2] == "scf.yield" and ops[i][4] == ops[loop][4] + 1)
inside = {ops[i][1] for i in range(loop + 1, end)} | {"%start", "%acc_1"}       # 循环变量和 iter_args 也算「里面」
invariant = []
for no, res, name, used, _ in ops[loop + 1:end]:
    if name != "tt.load" and not (set(used) & inside):          # load 读内存，这里保守地不动它
        invariant.append(f"{res} = {name}")
        inside.discard(res)                                       # 它被提出去了，用它的 op 也可能不变
print("③ 能提到循环外面的：" + "，".join(invariant))
```

运行结果：

```
① 方言：tt 13 个，arith 11 个，scf 5 个
② %row    定义：第 6 行 tt.get_program_id；被用到：第 13 行 arith.muli、第 33 行 tt.addptr
② %acc_1  定义：循环的 iter_args（块参数）；被用到：第 18 行 arith.addf
② %acc    定义：第 7 行 scf.for；被用到：第 21 行 tt.reduce
③ 能提到循环外面的：%cols = tt.make_range，%acc_4 = tt.splat，%acc_6 = arith.muli，%acc_7 = tt.addptr，%acc_8 = tt.splat
```

第 ③ 条值得多看一眼：`%acc_6 = arith.muli %row, %stride`（行号乘 stride）每一轮循环都一样，Python 源码里 `row * stride` 写在循环里，TTIR 也就老老实实放在循环里。我们的小程序找出了 5 个这样的 op。下一节会看到，Triton 的 `triton-licm` pass 做的正是这件事，提出去的恰好是这 5 个。这就是 pass 的本质：**读 IR，按某个规则改写 IR**。

## pass：看一次变换

Triton 的编译过程，就是一串 pass 依次改写同一个 module。想看每个 pass 做了什么，设两个环境变量：

```bash
MLIR_ENABLE_DUMP=row_sum MLIR_DUMP_PATH=dump.txt python my_kernel.py
```

- `MLIR_ENABLE_DUMP=1` 对所有 kernel 打开；写成 kernel 的名字，就只看这一个。它在每个 pass **之前**把整个 module 打印一遍（`python/src/ir.cc` 的 `enable_debug`；pass 之后只在失败时打印）。
- `MLIR_DUMP_PATH` 把输出写进文件，不设就打到标准错误。输出很长：`row_sum` 这么小的 kernel，也有四十多万字节。
- 磁盘缓存里已经有这个 kernel 时不会重新编译，也就什么都不打印。先清空 `TRITON_CACHE_DIR`，或者指向一个空目录（第 4 章）。

数一数 `// -----// IR Dump Before` 这一行出现了几次，就知道有多少个 pass：`row_sum` 编到 sm_86 是 73 个，在 Max 1100 上是 71 个。两边有一部分是同一批（`CanonicalizerPass`、`CSEPass`、`TritonLoopInvariantCodeMotion`、`ConvertTritonToTritonGPU`……），也有各自的（NVIDIA 的 `TritonGPUAccelerateMatmul` 对应 Intel 的 `TritonIntelGPUAccelerateMatmul`；第 15 章的 `TritonIntelGPUMaterializeBlockPointer`、第 17 章的 `TritonIntelGPUReduceVariableLiveness` 只在 Intel 这边）。第 19 章会把整条流水线摊开来讲。

另一个值得对比的是 `convert-triton-to-tritongpu`（`ConvertTritonToTritonGPU`）前后。这是从 TTIR 到 TTGIR 的那一步，op 几乎不变，变的是类型和 module 的属性：

```ttgir-norun
// 之前（TTIR）
module {
    %cst_0 = arith.constant dense<0.000000e+00> : tensor<256xf32>
// 之后（TTGIR）
#blocked = #ttg.blocked<{sizePerThread = [1], threadsPerWarp = [32], warpsPerCTA = [4], order = [0]}>
module attributes {"ttg.num-ctas" = 1 : i32, "ttg.num-warps" = 4 : i32, ttg.target = "cuda:86", "ttg.threads-per-warp" = 32 : i32} {
    %cst_0 = arith.constant dense<0.000000e+00> : tensor<256xf32, #blocked>
```

`tensor<256xf32>` 变成了 `tensor<256xf32, #blocked>`：类型后面多了一个**编码**（encoding）属性，说明这 256 个元素怎样分给线程：每个线程 1 个，一个 warp 32 个线程，4 个 warp。module 上也多了 `num-warps`、`threads-per-warp`、目标 GPU 这些属性。`#blocked = ...` 是一个**属性别名**：一长串属性起个短名字，下面用 `#blocked` 引用。**TTIR 和 TTGIR 的区别，本质上就是张量类型带不带 layout**。layout 是 Triton 最核心的设计，第 20、21 章专门讲。

这种「op 不变、类型变了」的改写，在 MLIR 里叫 **dialect conversion**；把高层方言一步步换成低层方言的过程，叫 **lowering**。Triton 的 lowering 是 TTIR → TTGIR → LLVM 方言 → LLVM IR → PTX / SPIR-V。框架层面的细节（`TypeConverter`、`ConversionTarget`、pattern 怎么写）在《深入 MLIR》第 13、14、16 章。读 Triton IR 用不到那么多，记住一点就够了：**每个 pass 的输入和输出都是合法的 IR**，所以任何两个 pass 之间都可以停下来看。

---

**这一章的要点**

- Triton 的每一级 IR 都是 MLIR。一行一个 **op**：`%结果 = 方言.op名 操作数 {属性} : 类型`，点号前面是方言。
- **值**是 SSA 的：每个只定义一次。名字（`%offs_2`）来自 Python 变量名（`printNameLocAsPrefix`），读 IR 先找名字就能对回源码；没名字的中间值是 `%0`、`%1`。
- **类型**：`tensor<1024xf32>` 是一个块，`!tt.ptr<f32>` 是指针；**属性**是编译期常量，函数参数上的 `tt.divisibility = 16` 就是第 4 章的特化。Python 里的隐式广播在 IR 里都是显式的 `tt.splat` / `tt.broadcast`。
- **region** 是 op 里装着的代码。循环里被修改的变量变成 `scf.for` 的 `iter_args` 和 `scf.yield`；运行时的 `if` 变成带返回值的 `scf.if`，constexpr 的 `if` 在前端就消失了；`tt.reduce` 的 region 是合并函数，block 参数是两个待合并的值。
- **pass** 读 IR、改写 IR。`MLIR_ENABLE_DUMP=<kernel>` 加 `MLIR_DUMP_PATH` 拿到每个 pass 之前的 IR（要先清缓存）；sm_86 上 73 个 pass，Max 1100 上 71 个。`triton-licm` 把 5 个循环不变量提到了循环外；`convert-triton-to-tritongpu` 给张量类型加上了 `#blocked` layout，这就是 TTIR 和 TTGIR 的区别。对比不同 pass 的 IR 时不要靠编号。
