# 第 16 章 Dialect Conversion（一）：TypeConverter、ConversionTarget 与部分转换

## 这一章想让你带走什么

<div class="goal-box">
<p>Dialect Conversion 是 MLIR 最难也最躲不开的一块——所有"从高层方言降到低层方言"的工作都走它。它和第 14 章那个 pattern 引擎是**两套东西**，别混：后者是"把 IR 改得更好"，前者是"把 IR 改成另一套方言能表达的样子"，多出了<strong>类型转换</strong>和<strong>合法性</strong>这两个维度。</p>
<p>这一章拆开它的四个部件，各配一段真代码：<strong>ConversionTarget</strong>（什么算合法）、<strong>TypeConverter</strong>（类型怎么换）、<strong>ConversionPattern</strong>（和普通 pattern 差在哪）、以及 <strong>driver</strong>（partial 还是 full）。落地物是一个 <code>pix-to-arith</code> pass：把 <code>pix.add</code>/<code>pix.mul</code>/<code>pix.scale</code> 降成 <code>arith</code> 和 <code>tensor</code> 的 op。</p>
<p>三个容易搞错的点会被实测钉住。<strong>一</strong>：合法性不是"合法/非法"两态，而是<strong>四态</strong>，多出来的 <code>Unknown</code> 才是 partial 与 full 的真正分界。<strong>二</strong>：<code>TypeConverter</code> 必须显式写"其他类型原样保留"这条身份规则，否则连 <code>tensor&lt;4x4xf32&gt;</code> 都过不去。<strong>三</strong>：写 pattern 时要用 <code>adaptor</code> 给的操作数，不能用 <code>op.getLhs()</code>。</p>
<p>结尾我们会故意制造一次失败，得到那句臭名昭著的报错——<code>failed to legalize unresolved materialization</code>。它就是第 17 章的入口。</p>
</div>

## 它和普通 pattern 差在哪

先把边界划清楚，否则后面全是混乱：

| | greedy pattern（第 14 章） | dialect conversion |
| --- | --- | --- |
| 目的 | 把 IR 改得更好 | 把 IR 改成另一套方言 |
| 什么时候停 | 到达不动点（没人能再改） | 达到"全部合法"（由 target 定义） |
| 类型能变吗 | 基本不变 | **这是它的核心能力** |
| 失败长什么样 | 不会失败，只是没改动 | **会失败**，而且报错很难读 |
| driver | `applyPatternsGreedily` | `applyPartialConversion` / `applyFullConversion` |

最后一行的差别很实在：greedy driver 没有"失败"这个概念——pattern 都不匹配就是 IR 没变。而 conversion driver 有明确的成功条件，达不到就整个 pass 失败。**这也是它报错难读的根源：失败是在"全局检查"那一步发现的，离真正的原因很远。**

## 部件一：`ConversionTarget` —— 合法性是四态

```cpp-norun
ConversionTarget target(*ctx);
target.addLegalDialect<arith::ArithDialect, tensor::TensorDialect,
                       func::FuncDialect>();

// 只把**有下降路径**的那几个标成非法。
target.addIllegalOp<AddOp, MulOp, ScaleOp>();
```

注意我对 `pix.reduce`、`pix.convolve`、`pix.pipeline` **一个字都没说**。它们既没被标合法、也没被标非法——这是第四种状态。`mlir/include/mlir/Transforms/DialectConversion.h:1265` 那段注释说得很清楚：

```cpp-norun
/// Note: Legality is actually a 4-state: Legal(recursive=true),
/// Legal(recursive=false), Illegal or Unknown, where Unknown is treated
/// either as Legal or Illegal depending on context.
```

**`Unknown` 视上下文当作合法或非法**——而那个"上下文"就是你选了 partial 还是 full。官方文档（`mlir/docs/DialectConversion.md:20`）对 partial 的定义是："will allow pre-existing operations that were **not explicitly marked as illegal** to remain unconverted."

把这四态记住，`failed to legalize` 里一半的困惑就没了。

四种声明方式，各有用途：

| 写法 | 含义 |
| --- | --- |
| `addLegalDialect<D>()` / `addLegalOp<Op>()` | 静态合法 |
| `addIllegalDialect<D>()` / `addIllegalOp<Op>()` | 静态非法，**必须**被换掉 |
| `addDynamicallyLegalOp<Op>(回调)` | 逐个实例问回调。**下降到一半的中间状态全靠它** |
| 什么都不说 | `Unknown` |

第三种最值得留意。真实下降里经常需要"这个 op 合不合法取决于它的操作数类型"——比如 `func.func` 在签名还没转换完之前非法、转换完之后合法。第 17 章会大量用到它。

## 部件二：`TypeConverter` —— 第一条规则最容易漏

```cpp-norun
class PixTypeConverter : public TypeConverter {
public:
  PixTypeConverter() {
    // ① 身份规则：默认原样保留。必须有。
    addConversion([](Type ty) { return ty; });

    // ② !pix.kernel<R x C> → tensor<RxCxf32>
    addConversion([](KernelType kty) -> std::optional<Type> {
      return RankedTensorType::get({kty.getRows(), kty.getCols()},
                                   Float32Type::get(kty.getContext()));
    });
  }
};
```

<div class="warn">
<strong><code>TypeConverter</code> 默认什么都不认</strong>
<p>漏掉第一条身份规则，<code>tensor&lt;4x4xf32&gt;</code> 这种<strong>你根本没打算换</strong>的类型也会被判成"无法转换"，于是连函数签名都过不去，报错指向一个完全无辜的地方。<strong>写 <code>TypeConverter</code> 的第一件事就是补上 <code>addConversion([](Type ty) { return ty; });</code></strong>，然后才轮到你真正关心的那几条。</p>
<p>另外注意返回值的三种含义：返回一个 <code>Type</code> = 换成它；返回 <code>std::nullopt</code> = "我不管这个类型"（交给别的规则）；返回**空** <code>Type{}</code> = "这个类型转换失败"。<code>nullopt</code> 和空 Type 完全不同，混了会得到很难查的行为。</p>
</div>

规则是**后注册的先试**（像栈一样），所以特化的规则要放在身份规则之后。

## 部件三：`ConversionPattern` —— 必须用 adaptor

和 `OpRewritePattern` 比，签名只多一样东西：

```cpp-norun
struct AddLowering : OpConversionPattern<AddOp> {
  using OpConversionPattern::OpConversionPattern;

  LogicalResult matchAndRewrite(AddOp op, OpAdaptor adaptor,
                                ConversionPatternRewriter &rewriter) const override {
    rewriter.replaceOpWithNewOp<arith::AddFOp>(op, adaptor.getLhs(),
                                               adaptor.getRhs());
    return success();
  }
};
```

那个 **`adaptor`** 是这一章第二个要点。它装的是**已经被转换过的操作数**。

<div class="keypoint">
<strong>用 <code>adaptor.getLhs()</code>，不要用 <code>op.getLhs()</code></strong>
<p>转换是<strong>逐步</strong>进行的：当 driver 处理你这个 op 时，它的操作数可能已经被别的 pattern 换成了新类型的值。<code>op.getLhs()</code> 给你的是<strong>旧</strong>的那个（类型还是旧的、甚至已经准备被删掉），<code>adaptor.getLhs()</code> 给你的是<strong>当前该用的</strong>。</p>
<p>这是 conversion pattern 最高频的错误来源，而且症状很隐蔽：类型没变的地方两者一样，所以代码"看起来能跑"，直到某天类型真的变了才炸。<strong>养成习惯：在 conversion pattern 里永远只碰 adaptor</strong>，`op` 只用来取位置、属性和"要替换谁"。</p>
</div>

一个 pix op 变成两个 op 完全正常：

```cpp-norun
// pix.scale %img, %f → arith.mulf %img, tensor.splat %f
struct ScaleLowering : OpConversionPattern<ScaleOp> {
  using OpConversionPattern::OpConversionPattern;

  LogicalResult matchAndRewrite(ScaleOp op, OpAdaptor adaptor,
                                ConversionPatternRewriter &rewriter) const override {
    auto ty = dyn_cast<RankedTensorType>(adaptor.getImage().getType());
    if (!ty)
      return rewriter.notifyMatchFailure(op, "图不是有阶张量，splat 不出来");

    Value splat = tensor::SplatOp::create(rewriter, op.getLoc(), ty,
                                         adaptor.getFactor());
    rewriter.replaceOpWithNewOp<arith::MulFOp>(op, adaptor.getImage(), splat);
    return success();
  }
};
```

（`arith` 的浮点运算在 tensor 上就是逐点的，所以 `pix.add` → `arith.addf` 这么直接。这一步不需要 `linalg`——那是第 20 章为了 tiling 才需要的。）

## 部件四：driver —— partial 还是 full

```cpp-norun
if (full) {
  if (failed(applyFullConversion(getOperation(), target, std::move(patterns))))
    signalPassFailure();
  return;
}
if (failed(applyPartialConversion(getOperation(), target, std::move(patterns))))
  signalPassFailure();
```

跑 partial：

```mlir-lower
// RUN: pix-opt %s --pix-to-arith
func.func @lowerable(%a: tensor<4x4xf32>, %b: tensor<4x4xf32>, %s: f32) -> tensor<4x4xf32> {
  %0 = pix.add %a, %b : tensor<4x4xf32>
  %1 = pix.mul %0, %b : tensor<4x4xf32>
  %2 = pix.scale %1, %s : tensor<4x4xf32>
  return %2 : tensor<4x4xf32>
}
func.func @has_reduce(%a: tensor<4x4xf32>) -> f32 {
  %0 = pix.add %a, %a : tensor<4x4xf32>
  %1 = pix.reduce %0 : tensor<4x4xf32> -> f32
  return %1 : f32
}
```

运行结果：

```
module {
  func.func @lowerable(%arg0: tensor<4x4xf32>, %arg1: tensor<4x4xf32>, %arg2: f32) -> tensor<4x4xf32> {
    %0 = arith.addf %arg0, %arg1 : tensor<4x4xf32>
    %1 = arith.mulf %0, %arg1 : tensor<4x4xf32>
    %splat = tensor.splat %arg2 : tensor<4x4xf32>
    %2 = arith.mulf %1, %splat : tensor<4x4xf32>
    return %2 : tensor<4x4xf32>
  }
  func.func @has_reduce(%arg0: tensor<4x4xf32>) -> f32 {
    %0 = arith.addf %arg0, %arg0 : tensor<4x4xf32>
    %1 = pix.reduce %0 : tensor<4x4xf32> -> f32
    return %1 : f32
  }
}
```

第一个函数全换掉了。第二个函数里 `pix.add` 换了，**`pix.reduce` 原样留着，而且这不算失败**——它是 `Unknown`，partial 放它过去。

换成 full：

```bash
pix-opt c16.mlir --pix-to-arith=full=true
```

运行结果（截取）：

```
c16.mlir:0:0: error: failed to legalize operation 'builtin.module'
```

**报错挂在最外层的 `builtin.module` 上**，而不是那个真正有问题的 `pix.reduce`。这个"报错离现场很远"的毛病是 dialect conversion 最招人恨的地方，第 17 章会给一套系统的排查法。

<div class="keypoint">
<strong>绝大多数真实下降都该用 partial</strong>
<p>理由不是"partial 更宽松"，而是<strong>下降天生是分阶段的</strong>。一条完整的下降管线（第四部分那条 pix → linalg → memref → vector → llvm）由十几个 pass 接力，每个 pass 只负责搬走自己认识的那部分 op。每一步都要求"全体合法"是不可能的。</p>
<p><code>full</code> 的正当用途只有一处：<strong>管线的最后一棒</strong>。到那时你确实需要保证"IR 里再没有任何非目标方言的东西"，一个漏网的 op 就意味着后面的代码生成会崩。把它当一道验收闸门用，别当成日常工具。</p>
</div>

## 把判定链自己跑一遍

四态判定和 partial/full 的差别，用一个小模型跑最清楚。下面这个 driver 模型会把"UNKNOWN 在两种模式下的不同命运"直接打出来：

```python
# 一个 50 行的 conversion driver 模型。要弄清三件事：
#   1. "合法"有三种：静态合法、静态非法、动态合法（看一个回调）
#   2. partial 与 full 的差别只在最后那一步检查
#   3. 类型变了而下游没跟上时，driver 会插一个 cast —— 解不掉就报错

class Target:
    """合法性是**四态**，不是两态（见 DialectConversion.h:1265）：
       LEGAL / ILLEGAL / DYNAMIC / UNKNOWN。
       UNKNOWN 的含义随上下文而变：partial 当它合法，full 当它非法。
       这是 partial 与 full 的**唯一**实质区别。"""
    def __init__(self):
        self.legal_dialects, self.illegal_ops, self.dynamic = set(), set(), {}
    def legal_dialect(self, *ds): self.legal_dialects.update(ds); return self
    def illegal_op(self, *ops): self.illegal_ops.update(ops); return self
    def dynamically_legal(self, op, fn): self.dynamic[op] = fn; return self

    def action(self, op):
        if op.name in self.dynamic:            # 动态：逐个 op 问回调
            return "LEGAL" if self.dynamic[op.name](op) else "ILLEGAL"
        if op.name in self.illegal_ops:
            return "ILLEGAL"
        if op.name.split(".")[0] in self.legal_dialects:
            return "LEGAL"
        return "UNKNOWN"                       # 什么都没说

    def is_legal(self, op, full):
        a = self.action(op)
        return a == "LEGAL" or (a == "UNKNOWN" and not full)

class Op:
    def __init__(self, name, result_type="tensor", operand_types=()):
        self.name, self.result_type = name, result_type
        self.operand_types = list(operand_types)
    def __repr__(self): return f"{self.name}:{self.result_type}"

def convert(ops, target, patterns, full):
    out, casts = [], []
    for op in ops:
        act = target.action(op)
        if act == "LEGAL":
            print(f"    {op.name}：LEGAL，不动")
            out.append(op); continue
        if act == "UNKNOWN" and op.name not in patterns:
            print(f"    {op.name}：UNKNOWN（partial 放过，full 判失败）")
            out.append(op); continue
        if op.name not in patterns:
            print(f"    {op.name}：ILLEGAL 但没有 pattern → 一定失败")
            out.append(op); continue
        new = patterns[op.name](op)
        print(f"    {op.name} → {new}")
        # 结果类型变了？下游还等旧类型的话，driver 要插一个 cast
        if new.result_type != op.result_type:
            casts.append((new.result_type, op.result_type))
            print(f"       类型变了：插一个 unrealized_conversion_cast "
                  f"{new.result_type} → {op.result_type}")
        out.append(new)

    # 最后一步：partial 只关心"还有没有没解决的 cast"；full 还要求全体合法
    leftovers = [op for op in out if not target.is_legal(op, full)]
    if casts:
        return out, f"失败：{len(casts)} 个 cast 没人物化（第 17 章的主题）"
    if full and leftovers:
        return out, f"失败：full 模式下 {leftovers} 是 UNKNOWN，被当作非法"
    if leftovers:
        return out, f"成功：partial 模式把 UNKNOWN 当合法，{leftovers} 原样留下"
    return out, "成功：全部合法"

target = (Target().legal_dialect("arith", "tensor", "func")
                  .illegal_op("pix.add", "pix.mul", "pix.scale"))
patterns = {
    "pix.add":   lambda op: Op("arith.addf", op.result_type),
    "pix.mul":   lambda op: Op("arith.mulf", op.result_type),
    "pix.scale": lambda op: Op("arith.mulf", op.result_type),
    # 这条会改结果类型：!pix.kernel → tensor
    "pix.kernel": lambda op: Op("arith.constant", "tensor<3x3>"),
}

CASES = [
    ("全部可降", [Op("pix.add"), Op("pix.mul"), Op("func.return")], False),
    ("有 pix.reduce（没标非法，也没 pattern）", [Op("pix.add"), Op("pix.reduce", "f32"), Op("func.return")], False),
    ("同样的输入换 full 模式", [Op("pix.add"), Op("pix.reduce", "f32"), Op("func.return")], True),
]
for title, ops, full in CASES:
    print(f"\n【{title}】mode={'full' if full else 'partial'}")
    _, verdict = convert(ops, target, patterns, full)
    print(f"  → {verdict}")

print("\n【类型变了而下游没跟上】mode=partial")
t2 = (Target().legal_dialect("arith", "tensor", "func")
              .illegal_op("pix.kernel"))
_, verdict = convert([Op("pix.kernel", "!pix.kernel<3x3>"),
                      Op("pix.convolve", "tensor", ["!pix.kernel<3x3>"])], t2, patterns, False)
print(f"  → {verdict}")
```

运行结果：

```

【全部可降】mode=partial
    pix.add → arith.addf:tensor
    pix.mul → arith.mulf:tensor
    func.return：LEGAL，不动
  → 成功：全部合法

【有 pix.reduce（没标非法，也没 pattern）】mode=partial
    pix.add → arith.addf:tensor
    pix.reduce：UNKNOWN（partial 放过，full 判失败）
    func.return：LEGAL，不动
  → 成功：全部合法

【同样的输入换 full 模式】mode=full
    pix.add → arith.addf:tensor
    pix.reduce：UNKNOWN（partial 放过，full 判失败）
    func.return：LEGAL，不动
  → 失败：full 模式下 [pix.reduce:f32] 是 UNKNOWN，被当作非法

【类型变了而下游没跟上】mode=partial
    pix.kernel → arith.constant:tensor<3x3>
       类型变了：插一个 unrealized_conversion_cast tensor<3x3> → !pix.kernel<3x3>
    pix.convolve：UNKNOWN（partial 放过，full 判失败）
  → 失败：1 个 cast 没人物化（第 17 章的主题）
```

注意第二组和第三组：**输入完全相同、pattern 完全相同，只换了 driver**，结果一个成功一个失败。差别的全部来源就是 `pix.reduce` 那个 `UNKNOWN` 的解释方式。

最后一组就是下一章的入口。

## 顺手补掉一个真 bug：`ConstantLike` 是个契约

写这一章时我打开了 `lower-kernels` 那个选项（把 `pix.kernel` 也降成 `arith.constant`），结果 `pix-opt` 直接断言失败：

```
pix-opt: mlir/include/mlir/IR/Matchers.h:93: bool mlir::detail::constant_op_binder<...>::match(Operation *):
Assertion `succeeded(result) && "expected ConstantLike op to be foldable"' failed.
```

原因在第 9 章。当时给 `pix.kernel` 加了 `ConstantLike` 这个 trait，只当它是"声明我是个常量"，没配 folder。而 `Matchers.h:93` 那段代码说明它是个**契约**：

```cpp-norun
if (!op->hasTrait<OpTrait::ConstantLike>())
  return false;
// Fold the constant to an attribute.
SmallVector<OpFoldResult, 1> foldedOp;
LogicalResult result = op->fold(/*operands=*/{}, foldedOp);
assert(succeeded(result) && "expected ConstantLike op to be foldable");
```

**任何标了 `ConstantLike` 的 op 都必须 `fold()` 成功**，否则谁用 `m_Constant` 匹配它就谁崩。补一行就好：

```cpp-norun
// 它不"化简"任何东西，纯粹是为了满足契约——让 m_Constant 这类匹配器
// 能从一个 pix.kernel 上取出常量值。
OpFoldResult KernelOp::fold(FoldAdaptor adaptor) { return getWeights(); }
```

这个 bug 从第 9 章一直潜伏到第 16 章，**因为直到 dialect conversion 才有人走那条常量折叠的路**。它是个很好的提醒：**trait 不只是标签，多数 trait 背后都有一条你必须履行的义务**——`ConstantLike` 要 foldable，`Terminator` 要在块尾，`IsolatedFromAbove` 要真的不引用外面（第 13 章那笔账）。加 trait 前先去看它的文档和断言。

## 动手：给 `pix.reduce` 一条动态合法规则

现在 `pix.reduce` 是 `Unknown`，full 模式下必然失败。改成"只有当它的输入还是 `pix` 方言产出的时候才算非法"——这是真实下降里 `addDynamicallyLegalOp` 最常见的用法：

```cpp-norun
target.addDynamicallyLegalOp<ReduceOp>([](ReduceOp op) {
  // 输入已经是 arith/tensor 产出的 → 我们暂时认它合法
  Operation *def = op.getImage().getDefiningOp();
  return !def || def->getDialect()->getNamespace() != "pix";
});
```

加完跑 `--pix-to-arith=full=true`，看那句 `failed to legalize` 有没有变。

**再改一处**：把 `PixTypeConverter` 里那条身份规则 `addConversion([](Type ty) { return ty; });` 注释掉，重新构建，跑 `--pix-to-arith`。你会得到一个指向函数签名、和 `pix.add` 毫无关系的报错——**亲手撞一次，以后写 `TypeConverter` 第一行就不会忘**。

---

**这一章的要点**

- **dialect conversion 和 greedy pattern 是两套东西**：后者追求不动点、不会失败；前者追求"全体合法"、会失败，而且多了类型转换这个维度。
- **合法性是四态，不是两态**：`Legal(递归)` / `Legal(非递归)` / `Illegal` / **`Unknown`**（`DialectConversion.h:1265`）。**`Unknown` 的解释方式就是 partial 与 full 的唯一实质区别**——partial 当它合法放过，full 当它非法失败。
- `addDynamicallyLegalOp` 是"下降到一半"这种中间状态的唯一表达方式，真实管线里用得极多。
- **`TypeConverter` 的第一条必须是身份规则** `addConversion([](Type ty) { return ty; })`。漏了它，连你根本没打算换的类型都过不去，而报错会指向一个无辜的地方。
- `addConversion` 回调的三种返回值含义不同：`Type` = 换成它，`std::nullopt` = 我不管，**空 `Type{}` = 转换失败**。规则是后注册的先试。
- **conversion pattern 里永远用 `adaptor` 取操作数**，不要用 `op.getXxx()`。后者给的是旧值。类型没变时两者相同，所以这个错误"看起来能跑"，直到类型真的变了才炸。
- **绝大多数真实下降用 partial**，因为下降天生分阶段。`full` 的正当用途只有"管线的最后一棒"，当验收闸门用。
- **`failed to legalize operation 'builtin.module'` 这种报错会挂在最外层**，离真正的原因很远。第 17 章专门讲怎么读。
- **trait 多数是契约，不只是标签**。`ConstantLike` 要求 op 必须 `fold()` 成功（`Matchers.h:93` 的断言），我们从第 9 章欠到这一章才补上。加 trait 前先看它的文档和断言。
